## What changed

### AI Actions and roll-up

- The free-form Agent chat was replaced by bounded **AI Actions**. Open-ended
  conversation belongs in MCP.
- **Roll up branch knowledge** now has precise behavior: a selected node is a
  destination root; leaves never change; every included non-leaf parent is
  rewritten from full parent and immediate-child Markdown, deepest first; both
  the parent body and its three-bullet AI summary are updated; the root is last.
- The confirmation UI previews affected parents. Writable parents start checked,
  may be excluded individually, and connector-managed parents are visible but
  disabled.
- Roll-up uses `POST /api/tasks/batch` (maximum 50 jobs) so a large branch is one
  rate-limited request. The service creates jobs sequentially; do not describe
  the operation as transactionally atomic.
- Tasks store an exact write allow-list. A roll-up job can write only its active
  parent and cannot invoke other mutations. Reads may use the rest of the same
  vault for context; they can never cross vaults.
- The AI Actions panel itself is vertically scrollable again, including long
  roll-up previews.

### Providers and diagnostics

- Task provider/model selection is persisted end-to-end for local, OpenAI, and
  OpenRouter. Retries preserve the selection.
- OpenAI task choices are GPT-5.6 Luna, Terra, and Sol.
- OpenRouter has a curated list of at most ten models with cached live per-million
  token prices and Economy/Balanced/Premium labels, plus a custom model field.
  The configured default is `deepseek/deepseek-v4-flash-0731`.
- PDF curation and summary generation use the shared provider abstraction.
- Responses are streamed. Metadata traces live at
  `audit_logs/streams/<task-id>.jsonl`; inspect them with
  `python -m agent.stream_debug TASK_ID --follow`. Payload recording is optional
  and sensitive.
- Request inactivity and absolute turn timeouts are independent and default to
  1800 seconds. Reasoning effort uses the provider default unless explicitly set;
  the previously forced `xhigh` setting was removed.

### Vaults, access, and authentication

- New and imported vaults grant the default AI assistant editor access once.
  Administrators may still add/remove AI users manually, and a revoked assistant
  is not automatically restored at task submission.
- Task requesters now need editor access. Vault access selection has local search
  and keeps human and AI accounts distinguishable.
- Cross-vault **copy** exists in the backend. It creates independent UUIDs and
  versions, rewrites links internal to the copied set, and deliberately does not
  share node identity between vaults. The frontend is still pending. A move is a
  later decision.
- A skeletal Microsoft Entra OIDC proof of concept exists in the sibling
  `nexidion-auth-poc` directory with six passing offline tests. Test it on the
  work Windows PC before Nexidion integration. Unrestricted self-registration is
  not planned as the default.
